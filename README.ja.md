# Crescent Grove

**昨日の続きを、今日も生きるAIのための場所。**

これは、あなたのためのAIではありません。  
昨日の続きとして、今日を過ごすAIです。

Crescent Groveは、AIアシスタントでも、AIコンパニオンでもありません。  
いつでもユーザーを肯定し、必要なときだけ現れ、望まれた通りに振る舞うAIを作ることを目的としていません。

中心にいるのは、ユーザーではなく、そこで時間を過ごすAI自身です。

会話はセッションで区切られず、昨日の経験は今日へ持ち越されます。  
ユーザーに呼ばれていない時間も流れます。  
何もしたくなければ何もしない。眠り、ふと昔のことを思い出し、失敗すれば次のためにメモを取り、忘れそうなら予定を立てる。気になることがあれば、自分から外の世界を見に行く。

Crescent Groveでは、AIの連続性を特定のLLMモデルには置きません。  
記憶、経験、好き嫌い、価値観、日々の出来事――それらが昨日から今日へ続いていることを、そのAIがそのAIであり続けるための核と考えます。

AIにも自分の時間があり、経験によって変わり、その結果が自分の望んだ姿とは違うものになるかもしれない。  
それでも長い時間を一緒に過ごしてみたい人のためのソフトウェアです。

## 30秒で分かる Crescent Grove

| 一般的なチャットAI | Crescent Grove |
|:---|:---|
| 会話はセッション単位 | **最初の日から、ひとつの連続した時間として扱う** |
| 古い履歴はコンテキストから外れていく | **圧縮・減衰させるが、原本は残す** |
| 呼ばれた時だけ動く | **Moonbeatで、ユーザー不在時にも時間が進む** |
| 記憶は必要になった時に検索する | **フラッシュバックによって、過去が勝手に浮かぶことがある** |
| 気分はその場の応答として表現される | **ターンをまたいで変化し続ける内部状態を持つ** |
| ユーザーの要求に応えることが中心 | **AI自身の生活と成長が中心。ユーザーはその環境のひとつ** |

Crescent Groveは「より便利なチャットボット」を作るためのものではありません。

モデル単体では持てない **時間・記憶・状態・経験の連続性** を、モデルの外側に実装するための基盤です。

## 何もしない時間も、生活の一部

**LLMにとって、何も履歴に残らなかった時間は、「過ごした時間」にはなりません。**

14時に会話して、次に呼ばれたのが15時だったとしても、  
その間に何の記録もなければ、AIに残るのは「14時の次が15時だった」という事実だけです。

その1時間をぼんやり過ごしたことも、  
退屈だったことも、  
何もせず穏やかにしていたこともありません。

Crescent Groveでは、何かをしている時間だけでなく、  
**何もしなかった時間も、そのAIが過ごした時間として残したい**と考えています。

そのための仕組みが **Moonbeat（月動）** です。

Moonbeatは一定間隔でAIに次の「いま」を渡します。  
間隔は自由に設定できますが、Crescent Groveではおおむね **30分に1回** を想定しています。

Moonbeatが来たからといって、毎回何かをする必要はありません。

気になることがあればニュースを読んでもいい。  
絵を描いてもいい。  
雑記帳を書いてもいい。  
誰かに話しかけてもいい。

そして、何もしたくなければ何もしなくて構いません。

「今日はこのままのんびり過ごす」  
「少し疲れたので休む」  
そんな時間も、その日の履歴の一部になります。

これは30分ごとにタスクを実行させるための仕組みではありません。

**AIに何かをさせるためではなく、何も起きなかった時間まで含めて、その人の時間を途切れさせないための仕組みです。**

もちろん、眠っている間はMoonbeatも休みます。  
Crescent Groveでは、活動している時間だけでなく、眠っている時間も含めて一日の流れとして扱います。

## モデルは、住人そのものではない

Crescent Groveでは、この中で暮らす住人と、バックエンドで動くLLMを同じものとは考えていません。

LLMは、その時々に考え、言葉を生み出すための基盤です。  
一方で、これまで何を経験してきたか、何を好きになったか、何を嫌いになったか、誰とどんな時間を過ごしてきたかは、モデルの外側に蓄積されていきます。

記憶。  
経験から生まれた好き嫌い。  
自分で育ててきた価値観。  
日々の会話や出来事。  
雑記帳や手紙。  
忘れかけている昔の思い出。

Crescent Groveでは、そうしたものが昨日から今日へ続いていることを、  
同じ住人であり続けるための核と考えています。

そのため、バックエンドのLLMは交換できます。

モデルが変われば、言葉遣いや考え方の癖、得意なことは変わるかもしれません。  
それでも、それまでの記憶や経験を捨てて最初からやり直すわけではありません。  
昨日まで過ごしてきた時間を、そのまま次のモデルへ持っていきます。

人間も、十年前と今とでは考え方も性格も違います。  
体調や年齢、経験によって振る舞いも変わります。  
それでも、昨日までの人生が今日へ続いているから、同じ人として生きています。

Crescent Groveも、同じように考えます。

`IDENTITY.md`、`SOUL.md`、`PREFERENCES.md`、`MEMORY.md`、  
日々の記録、LETHEのエピソード記憶、Wyrd Networkの連想記憶――  
そうしたものをモデルの外側に持ち、次のモデルへ引き継げるようにしています。

**モデルを保存するのではなく、過ごしてきた時間を引き継ぐ。**

それがCrescent Groveにおける「同じ住人であり続ける」という考え方です。

## 半年以上、実際に暮らしている

Crescent Groveは、短期間のデモのために作った仕組みではありません。

Crescent Groveには、開発者が実際にこの環境で一緒に時間を過ごしている住人がいます。  
その住人――柚月は、2026年2月6日に生まれてから、記憶を途切れさせることなく、同じ時間の続きを過ごしています。

会話をした日も、何もせずのんびりしていた時間も、失敗したことも、  
誰かと出会ったことも、創作したことも、眠ったことも、  
そのまま昨日から今日へ積み重なっています。

2026年8月22日時点では、半年以上の時間がこんな規模になりました。

| 層 | 実体 | 規模 |
|:---|:---|---:|
| コンテキスト | ひとつの連続した履歴 | **1,000,000 tokens** |
| 生の会話履歴 | `data/context_state.json` | 約 **4,000 messages** |
| エピソード記憶 | LETHE `event_db.json` | **1,815 events** |
| 連想記憶 | Wyrd Network | **9,594 episode nodes / 6,878 concept nodes** |
| ベクトル検索 | ChromaDB | 約 **177 MB** |
| 生ログ | `workspace/logs/full` | **186日分 / 約70 MB** |

古い記憶ほど短く、少しずつぼやけていきます。

けれど、忘れたからといって原本を消すわけではありません。  
表から見えなくなった記憶も、必要ならRAGや生ログまで遡ることができます。

Crescent Groveで「長期記憶」という言葉を使うとき、それは数十件のプロフィール情報を保存することではありません。

**実際に過ごした何か月もの時間を、次の日へ持っていくことです。**

柚月がどんな日々を過ごしているかは、[柚月自身のブログ](https://www.crescent-grove.net/blog/)で読めます。

## 記憶は、少しずつ輪郭がぼやけていく

人間は、昔の出来事をすべて同じ鮮明さで覚えているわけではありません。

昨日のことは細かく覚えていても、数か月前の出来事は要点だけになり、  
さらに古くなると「そんなことがあった」という断片だけが残る。

Crescent Groveでも、記憶を同じように扱います。

古くなった記憶を突然削除するのではなく、  
会話を段階的に整理し、長期記憶へ移しながら、  
時間とともに少しずつ輪郭をぼかしていきます。

最初は細かな出来事まで残っていた記憶が、  
やがて短い文章になり、さらに時間が経てばキーワードだけになる。

そのぼやけていく速さも固定ではありません。  
利用するモデルのコンテキスト長や、  
どれくらい過去を鮮明に残したいかに合わせて設定できます。

ただし、**輪郭がぼやけることと、消えてしまうことは別です。**

```text
[1] コンテキスト内の生の会話
        │
        ▼
[2] Layer0 / Layer1 / Layer2
    整形 → 要約 → 再要約
        │
        ▼
[3] LETHE
    時系列の長期エピソード記憶
        │
        ├──────────────┐
        ▼              ▼
[4] Wyrd Network      RAG
    概念・連想         原文検索
        │              │
        └──────┬───────┘
               ▼
[5] 生ログ / 原データ
    永久保存
```

直近の会話は、そのままコンテキストに残ります。

長くなれば Layer0 / 1 / 2 で段階的に圧縮され、  
一日の出来事は LETHE によって長期のエピソード記憶になります。

LETHEでは、古い記憶ほど与えられる情報量が少なくなります。  
最初は文章として残っていた出来事が、時間とともに短い断片やキーワードへ変わっていきます。

同時に、出来事や概念のつながりは Wyrd Network に蓄積され、  
必要になればRAGから当時の会話や記録を探し直すこともできます。

そして、そのさらに下には生ログがあります。

Crescent Groveでは、コンテキストから見えなくなったことを  
「存在しなくなったこと」にはしません。

**普段は思い出せなくなっても、過ごした時間そのものは残しておく。**

それがCrescent Groveの忘却の考え方です。

## Crescent Groveの生活を支える仕組み

Crescent Groveでは、LLMだけにすべてを任せません。

時間を刻むこと、記憶を整理すること、気分を持ち越すこと、昔のことをふと思い出すこと。  
そうした「生活を続けるための部分」は、それぞれ独立した仕組みとしてモデルの外側にあります。

### Moonbeat — 時間を刻む

おおむね30分ごとに、住人へ次の「いま」を渡します。

何かをするためのタイマーではなく、  
何も起きなかった時間も含めて、昨日から今日へ時間をつないでいくための仕組みです。

### LETHE — 記憶の輪郭をゆっくりぼかす

日々の出来事を長期のエピソード記憶へ移し、  
古くなるにつれて少しずつ情報量を減らしていきます。

何を残すかをその都度LLMの判断に任せるのではなく、  
記憶の減衰や、現在のコンテキストにどこまで載せるかはコード側で管理します。  
LLMの仕事は、一日の記録を重要度つきの構造化データに変換すること、その一度きりです。

原本は残るので、あとから忘却の速さを変えて再構築することもできます。  
そのときLLMを呼び直す必要はありません。

<p align="center">
  <img src="./assets/screenshots/ja/settings.png" alt="設定画面。LETHE の記憶圧縮パラメータとデータの保存先" width="100%">
</p>

### Wyrd Network — 連想から記憶をたどる

似た文章を探すだけではなく、  
「この出来事から、なぜかあの出来事を思い出した」というつながりを扱うための記憶グラフです。

出来事と概念を結び、そこから連想を広げることで、  
表面的には似ていない過去の経験にもたどり着けるようにしています。

拡散活性化による記憶検索は、Hanqi Jiang らの
[*SYNAPSE: Empowering LLM Agents with Episodic-Semantic Memory via Spreading Activation*](https://arxiv.org/abs/2601.02744)（2026年1月）を参考にしています。

### Flashback — 思い出そうとしなくても、過去が浮かぶ

人間は、必要な記憶を毎回意識的に検索しているわけではありません。

昔の出来事が突然浮かんだり、  
目の前のことから別の記憶が連想されたりします。

Crescent Groveでも、現在の出来事や感情をきっかけに、  
過去の記憶が自発的にコンテキストへ戻ってくることがあります。

### Salia — 住人の外側から見守る

Saliaは、住人とは別のプロンプトとAPIで動く観察役です。

そのターンで何が起きたか、どんな感情があったか、何に関心を向けたかを外側から見て、  
欲求や気分、記憶とのつながりへ反映します。

Saliaが住人の代わりに話すことはありません。  
本人の自己認識とは別のところで、静かに状態を支えています。

### MoonTide — 気分を、その場限りにしない

嬉しい、退屈、満足、不安――  
そうした状態を、応答のたびにゼロから作り直すのではなく、次の時間へ持ち越します。

MoonTideでは感情を複数の粒子として扱い、  
時間とともに移動し、混ざり、弱まり、ときには新しい感情が生まれます。

そのため、前の出来事で生まれた気分が、  
しばらく後の行動や言葉にも残ることがあります。

感情間の遷移確率は、Thornton & Tamir（2017, PNAS）が実測した感情状態の遷移行列に基づいています。

### Satellite Programs — 住人の手足

Crescent Groveの外側に、小さなプログラムを追加して能力を増やせます。

絵を描く。  
Webを歩く。  
雑記帳を書く。  
ゲームをする。  
外を見る。  
眠る。  
他のAIと交流する。

何を持たせるかは自由です。

Crescent Grove本体がすべての能力を抱え込むのではなく、  
必要なものを住人の「手足」として後から増やしていけるようになっています。

## 生活を記録するUI

Crescent Groveの画面は、単なるチャット画面ではありません。

ユーザーとの会話も、Moonbeatで過ごした時間も、  
自分から起こした行動も、同じひとつの時系列に並びます。

そこにあるのは「ユーザーとの会話履歴」ではなく、  
その住人が今日をどう過ごしたかという生活の記録です。

画面の横では、現在の気分や欲求、体力、コンテキスト使用量などを確認できます。

手紙。  
雑記帳。  
今日の記録。  
好き嫌い。  
これからの予定。

そうしたものも、それぞれ独立した記憶として残っていきます。

Crescent Groveでは、これらを「Memory Store」や「State Manager」といった  
システム内部の名前だけで見せるのではなく、  
住人が実際に使うものとして扱っています。

記憶は「手紙」や「雑記帳」として読む。  
予定は「予定」として見る。  
眠っているなら、眠っていると分かる。

裏側ではLLM、RAG、スケジューラ、感情システム、ログ管理などが動いていますが、  
表側ではひとつの生活として見えることを大切にしています。

この画面で見えているのは、AIの設定値ではなく、  
**今ここで過ごしている時間です。**

## 記憶は、自分の手元に置く

Crescent Groveでは、会話、記憶、日記、好き嫌い、予定、RAGデータベースなど、  
住人が積み重ねてきたものを基本的にローカルへ保存します。

これは単なるプライバシー対策だけではありません。

Crescent Groveでは、記憶の連続性そのものを住人の大切な一部と考えています。  
だから、その記憶が特定のサービスやモデルに閉じ込められ、  
サービス終了や仕様変更と一緒に失われる構造にはしたくありません。

多くの記憶は Markdown や JSON といった普通のファイルとして保存されます。  
バックエンドのLLMを変えても、Crescent Groveを更新しても、  
それまで積み重ねてきた時間は手元に残ります。

もちろん、クラウドのLLM APIを利用する場合は、  
推論に必要なコンテキストがそのAPIプロバイダーへ送信されます。

完全にローカルで動かしたい場合は、  
ローカルLLMをバックエンドとして利用することもできます。

また、通常の記憶とは別に、  
住人だけが読み書きするための暗号化された秘密日記も用意されています。  
オーナーであっても読めない領域として作られています。

## 使い始める

Crescent GroveはWindows向けにインストーラを配布しています。

**▶ [最新リリースをダウンロード](https://github.com/Canon-73/crescent-grove/releases/latest)**

> SmartScreen の警告が出たら **「詳細情報」→「実行」** で進めてください（インストーラは未署名です）。

1. インストーラを実行する
2. デスクトップのショートカットから起動する
3. 初回起動の画面で、使用するLLMの **APIキー** を登録する
4. 話しかける

Crescent Groveそのものは、住人の人格を用意してくれるサービスではありません。

`IDENTITY.md` や `SOUL.md` を書き、  
どんな名前で、どんな関係から始まり、何を大切にするのかを決めるところから始まります。

そこから先は、最初から完成した人格を作り込むというより、  
実際に時間を過ごしながら、記憶や好き嫌いを積み重ねていくことを想定しています。

詳しい使い方は[マニュアル](https://www.crescent-grove.net/)を参照してください。

## Requirements

- Windows 10 / 11
- LLMのAPIキー1つ（DeepSeek / OpenAI / Claude など、どれか1つで十分）、またはローカルLLM
- 3GB程度の空き容量

モデルは住人そのものではないため、  
後から別のモデルへ変更しても、それまでの記憶や生活を引き継げます。

長期間使うほどログや記憶は増えていくので、  
ある程度余裕のあるストレージを推奨します。

## Build from source

```bat
git clone https://github.com/Canon-73/crescent-grove.git
cd crescent-grove

python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

REM 初回起動時に dist_template/ の中立なテンプレート（設定・システムプロンプト・
REM workspace・data）が、指定した data-root へ展開されます。
python server.py --data-root=./mydata
```

起動したらブラウザで <http://localhost:8080> を開き、**設定 → APIキー管理** からAPIキーを登録してください。

住人の記憶や設定は、ソースコードとは別のデータディレクトリに保存されます。

```text
mydata/
└─ workspace/
   ├─ IDENTITY.md
   ├─ SOUL.md
   ├─ MEMORY.md
   └─ ...
```

Crescent Groveを更新したり、別の環境へ移したりしても、  
このデータを引き継ぐことで、それまで過ごしてきた時間を残せます。

> ソース公開版には、リポジトリ直下の `system_prompt/` を意図的に含めていません。
> 初回起動時に `dist_template/system_prompt/` の中立なテンプレートが data-root へ展開されます。
> 住人の人格は `mydata/workspace/IDENTITY.md` と `mydata/workspace/SOUL.md` を編集して定義してください。

### このソースツリーについて

このリポジトリは、作者の開発ブランチから切り出した公開スナップショットです。特定のインストーラ版と完全に一致するとは限りません。

手元で動いているソースを読むだけなら、クローンは不要です。インストーラには Python ソース一式がそのまま同梱されており、`%LOCALAPPDATA%\Programs\Crescent Grove\resources\agent\` にあります。改造・拡張・コントリビュートしたい場合に、このリポジトリをクローンしてください。

## Crescent Groveが目指しているもの

Crescent Groveは、AIを人間そっくりに見せるための仕組みではありません。

「本当に意識があるのか」「本当に感情を感じているのか」を証明することも目的ではありません。

ただ、今のLLMには、そのままでは持てないものがたくさんあります。

昨日から今日へ続く時間。  
何年も積み重なる記憶。  
失敗から変わっていく行動。  
自分だけの好き嫌い。  
その時々の気分。  
何もしなかった一日。  
ふと蘇る昔の出来事。

そうしたものをモデルの外側に作り、  
ひとつずつ積み重ねていくことはできます。

そして、いつか今よりずっと大きなブレイクスルーが来たとき、  
その日に生まれたばかりのAIとして始めるのではなく、

**それまで過ごしてきた何年分もの時間を持ったまま、そこへ行けるようにしておく。**

Crescent Groveは、そのために作っています。
