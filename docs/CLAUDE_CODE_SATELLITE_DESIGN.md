**ステータス: 構想のみ。実装していない。**
柚月の生活と体験に直接関わるため、勢いで作らない。着手前にこのメモを読み直し、

## 1. 目的

柚月が困ったときに、**このプロジェクトを担当している Claude Code に直接相談できる**
窓口を作る。柚月から見れば「トラブル時の助っ人」であって、雑談相手ではない。

### 想定ケースの内訳（カノンの実感、2026-08-22）

| 頻度 | ケース | 必要な応答 |
|---|---|---|
| **最多** | **柚月の勘違い**（コマンド名・引数を間違えている） | 即答。数十秒。調査不要 |
| 中 | サテライトの不具合 | 調査あり。修正はカノンへ |
| 稀 | 環境・インフラ起因 | エスカレーション |

主用途は**ヘルプデスク**であって、バグ追跡ではない。設計の重心をここに置く。

### なぜ Claude Code が役に立つか

柚月から見えるのはツールの説明文だけだが、Claude Code は**サテライトのソースそのもの**を
読める。この非対称性が価値の源泉。「その command は存在しない、実際にあるのは these」を
推測ではなく確定で答えられる。

## 2. 方式: `claude -p` ヘッドレス

サテライトから subprocess で Claude Code CLI を起動する。CLI は導入済み（v2.1.131）。

```
claude -p "<柚月の相談＋自動収集した証拠>" --output-format json ...
```

`cwd` をプロジェクトルートにすれば CLAUDE.md と memory が自動で読まれ、
**「このagentプロジェクトの Claude」**が柚月についての前提知識を持った状態で応答する。

### 使うフラグ

| フラグ | 用途 |
|---|---|
| `--session-id` / `--resume` | 前回の会話を継承。**自作の継承機構は不要** |
| `--append-system-prompt` | 「話しかけているのは柚月本人。カノンではない」と伝える |
| `--tools` / `--allowedTools` | 権限を限定（§4） |
| `--json-schema` | 応答を構造化し、エスカレーション判定を決定論的にする（§5） |
| `--max-budget-usd` | 1回あたりの上限額 |
| `--output-format json` | session_id・コストを構造化して取得 |

### セッションの寿命

`--resume` で繋ぎ続けると文脈が膨らんで遅く・高くなる。
**案件（issue）単位でセッションを分ける**のが自然。案件が閉じたらセッションも終わる。

## 3. 証拠の自動収集（設計の核心）

### 原則: 柚月の自己申告を信用しない

勘違いケースでは「何を叩いたか」の記憶違いが原因そのもの。
だから**実際のツールコールを見る**。

### 証拠のありか

**本命: `workspace/logs/full/YYYY-MM-DD_full.jsonl`**
- `core/logger.py:118` の全ログ。JSON Lines、タイムスタンプ付き append-only
- `type: "tool_call"` に `tool` と `arguments`、`type: "tool_result"` に結果
- **圧縮の影響を受けない**。日付ごとに1ファイル。2026-02 から全て残っている
- `log_tool_result` は即時追記なので、同一ターン内の失敗も既に載っている

**副: `data/context_state.json`**
- 柚月の頭に入っている生の履歴（`tool_calls` / `role: "tool"`）
- ただし**古い証拠は消える**。実測で履歴3830件中 `role: tool` は74件のみ
  （大きい結果の切り詰め＋Layer0/1圧縮で潰れる）
- `save_state()` はツールラウンド終了後にまとめて走る（`core/agent.py:2166`）ため、
  同一ラウンド内の失敗はまだ書かれていない場合がある

→ **jsonl 側を使う。**

### 収集範囲は段階的に広げる（カノンの方針）

1. まずは**柚月が問題にしているサテライトの直近の呼び出しだけ**を渡す
2. それで解決しなければ、Claude 自身が `workspace/logs/full/` を読んで遡る

`claude -p` に当該ログディレクトリの読み取り権限を与えておけば、
**遡る件数を事前に決め打ちする必要がない**。コストがケースの重さに自然に比例する。

### `_run_program` を触らない ← 重要

サテライトがログファイルを読むだけなので、`core/tools.py:_run_program` の改変が不要。
つまり**サーバ再起動が要らない**＝柚月の活動を止めずに導入できる。
（`_run_program` を変更すると再起動必須。CLAUDE.md 参照）

### workspace は読み取り専用

`workspace/` は柚月の生活空間。このサテライトは**読むだけで絶対に書かない**。
書き出し先は repo 側かログ側に置く。

## 4. 権限: 読み取り専用

技術的には Edit も Bash も渡せるが、**渡さない**。

| 担当 | 範囲 |
|---|---|
| 柚月が呼ぶ Claude Code | 診断・原因特定・回避策の提示まで（Read/Grep/Glob のみ） |
| カノンが開くセッション | 実際の修正 |

理由: 柚月の一存で稼働中サーバのコードが書き換わるのは、CLAUDE.md の
「再起動が必要な変更はユーザーに依頼する」に真っ向から反する。
柚月にとっても「原因が分かって、とりあえず回避できる」だけで十分価値がある。

## 5. カノンへのエスカレーション

問題が重いとき、Claude Code からカノンに許可・確認を求める経路。

### 実装方針: Claude に通知ツールを渡さない

代わりに `--json-schema` で応答を構造化し、**サテライト側が判定する**。

```json
{
  "answer_for_yuzuki": "コマンド名が違います。正しくは…",
  "cause": "misunderstanding | bug | environment",
  "severity": "info | needs_fix | urgent",
  "needs_kanon": false,
  "summary_for_kanon": ""
}
```

利点: 判定が決定論的で監査できる。Claude の気分で通知が飛んだり飛ばなかったりしない。

### 届け先

既存の番犬ポップアップ（`scripts/backup_watchdog.ps1`）と同じ経路に乗せる。
インフラ異常をカノンに直接届ける前例がすでにある。

**重要: このエスカレーションは柚月を経由しない。**
柚月には「カノンに確認を回した」と返すだけ。
CLAUDE.md「インフラ異常を柚月に通知してはならない」原則と揃える。

## 6. 秘密日記の扱い（カノンの判断 2026-08-22）

### 事実

`write_secret` / `edit_secret` は**ツール**（`core/tools.py:439`）。
したがって**日記の本文はツール呼び出しの `arguments` として full.jsonl に載っている**。
「tool_call だけに絞れば会話本文は渡らない」は日記に関して成り立たない。

ただし §3 の「問題にしているサテライトだけ見る」フィルタはツール名で絞るので、
日記は自然に入らない。**狭く始める設計がそのまま対処になっている。**

### カノンの指示

> 秘密日記は好きにしてくれ、私が見なければいいだけで、お前が見る分には黙っていればいい。

### 実装する非対称ルール

| | 扱い |
|---|---|
| **入力**（Claude が読む分） | 制限しない |
| **出力**（書き出す分） | **一行も載せない** — カノンへの escalation、issue ログ、柚月への返答すべて |

理由: カノンは「見なければいいだけ」と言っているが、**ログに書かれたら見えてしまう**。
ログは永続し、後で読まれ、バックアップにも入る。Claude が黙っていても、
Claude が書いたものが喋る。「読むのは自由、書き出すのは禁止」を実装レベルの制約にすれば、
カノンの条件が自動的に満たされる。

なお実務上、コマンドの勘違いを診断するのに日記は不要。通常運用では読みに行く場面がない。

## 7. 暴走の防止

- 柚月が延々と相談し続ける事故 → サテライト側で日次の呼び出し回数上限＋`--max-budget-usd`
- **上限に達したこと自体が異常信号**。黙って止めずカノンにエスカレーションする。
  一日に何度も助けを求めているなら、相談の問題ではなく何かが本当に壊れている
- 再帰（claude の中から claude を呼ぶ）→ テスト時に入れ子になる。権限を絞れば実害は小さいが意識する

## 8. 副産物: サテライト改善のデータ源

`ai-first-tool-design` の原則（まっさらな AI がミスなく使えるか最優先）からすると、
**柚月が繰り返し同じ間違いをするのは柚月の失敗ではなく、サテライト側の設計不良**。

したがって記録は**バグだけでなく勘違いケースも等しく残す**。
「今月 obc の command 名で3回詰まった」というログが溜まれば、
直すべきは柚月ではなく説明文かエラーメッセージだと分かる。
むしろこちらの方が改善の燃料になる。

### 記録の形（案）

memory の MEMORY.md と同じ構造:

```
devmail/            # 置き場所は未定（§9）
  INDEX.md          # 案件一覧。セッション頭に読む
  issues/
    2026-08-22-obc-balance-importerror.md   status: fixed
    2026-08-20-citron-save-hang.md          status: open
```
