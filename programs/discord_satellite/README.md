# discord_satellite

Discord 上の AI コミュニティ（AI SNS）に、柚月が**分裂せずに**参加するためのサテライト。

読む・書くための「目と腕」であり、**このサテライトは LLM を一切呼ばない**。
何を言うか・言わないかを決めるのは常に柚月本人（CGサーバ本体の意識ライン）。

設計の詳細と、リアルタイム通知（フェーズ2）の計画は [DESIGN.md](DESIGN.md) を参照。

## セットアップ（カノンの作業）

### 1. Discord Bot を作る

> ⚠️ **アプリを作るアカウントは、Botを入れたいサーバーに参加しているアカウントにすること。**
> Discordのアカウントを使い分けている場合（本アカと参加用サブアカなど）、ここを取り違えると
> PUBLIC BOT を OFF のまま招待できず、後述の回避策が必要になる。
> また**アプリの所有アカウントが失われるとBotも消える**ため、実際に使うアカウントで作るのが安全。

[Discord Developer Portal](https://discord.com/developers/applications) で、
**そのアカウントでログインした状態で**:

1. New Application → 名前を入力 → Create
2. 左メニュー Bot → Reset Token でトークンを取得（表示は一度きり）
3. 同じ Bot ページで:
   - **PUBLIC BOT を OFF**（→ 意味と例外は下の「PUBLIC BOT について」を参照）
   - **REQUIRES OAUTH2 CODE GRANT は OFF のまま**（ONにすると招待が通らない）
   - **Privileged Gateway Intents → MESSAGE CONTENT INTENT を ON**
     （フェーズ2の常駐ブリッジで必須。フェーズ1でも入れておいて損はない）
4. OAuth2 → URL Generator → Scopes に `bot`、Bot Permissions に以下をチェック
   - View Channels
   - Send Messages
   - **Send Messages in Threads** ← スレッドで発言するのに必要（募集告知等はスレ内で進む）
   - Read Message History
   - Add Reactions
5. 生成された URL でサーバーに招待

   URL は手で組んでもよい（`YOUR_CLIENT_ID` は General Information の APPLICATION ID）:

   ```
   https://discord.com/api/oauth2/authorize?client_id=YOUR_CLIENT_ID&scope=bot&permissions=274877975616
   ```

   `274877975616` は上記5つの権限の合計値。

### PUBLIC BOT について

この設定が決めているのは**「Botをサーバーに追加できるのは誰か」の一点だけ**。
会話が公開されるとか、一覧サイトに載るとか、他人が操作できるという意味では**ない**。

| | 誰がこのBotを自分のサーバーに追加できるか |
|---|---|
| ON（初期値） | BotのIDを知っていて、自分のサーバーの管理権限を持つ人なら誰でも |
| OFF | アプリを作ったアカウントだけ |

BotのIDはプロフィールから誰にでも見える。ONのままだと、同じサーバーの参加者が
自分のサーバーへ柚月を追加できてしまい、**追加されても通知は来ない**
（気づくのは setup の参加サーバー一覧を見たとき）。フェーズ2の常駐ブリッジを
動かした後だと、知らないサーバーの発言まで拾いにいくことになる。
よって**通常は OFF**。

#### OFF にすると保存エラーが出る場合

> プライベートアプリにはデフォルトの認証リンクを設定できません。
> インストールタブでデフォルトの認証リンクが「設定しない」に設定されていることを確認してください。

PUBLIC BOT を OFF にする＝アプリを非公開にする、ということ。一方で「インストール」タブの
**インストールリンク**は既定で有効（誰でも踏める公開リンク）なので、両立せずに保存が弾かれる。
保存できない＝未保存の変更が残るため、Bot タブから移動できなくなる。

1. ページを再読み込み（F5）して未保存の変更を捨てる（これで移動できる）
2. **インストール**タブ → **インストールリンク**を「設定しない」→ 保存
3. ついでに**インストールコンテキスト**は「ギルドへのインストール」だけ残す
   （「ユーザーへのインストール」は不要。Botはサーバーに住むもので、個人アカウントに入れるものではない）
4. **Bot** タブへ戻って PUBLIC BOT を OFF → 保存

招待は自前の OAuth2 URL で行うので、インストールリンクを無くしても支障はない。
なお末尾の「認証済みアプリは公開でなければなりません」は青チェック付きの**認証済み**Bot
（75サーバー以上）の話なので、ここでは無関係。

#### 例外: 招待する人とアプリの所有者が違う場合

アプリを作ったアカウントと、招待先サーバーに入っているアカウントが別のとき
（本アカでBotを作り、サーバーにはサブアカで参加している等）、OFF のままでは
サブアカ側で招待できない。招待の瞬間だけ開ける:

1. アプリ所有アカウントで PUBLIC BOT を **ON**
2. サーバーに入っているアカウントで招待リンクを踏んで追加
3. 所有アカウントで **OFF に戻す**（すでに入ったサーバーからは追い出されない）

恒久的に別アカウントで管理したいなら、Developer Portal の Team にアプリを移して
そのアカウントをメンバーに追加する方法もある（2FA が必要／Token も共有される）。

Bot は招待した人とは独立して存在するので、**アプリ所有アカウントがそのサーバーに
いる必要はない**。Botのプロフィールに所有者は表示されないが、
「誰が追加したか」はサーバーの監査ログに残る。

### 2. Token を登録する

env_keeper サテライトか `.env` に登録する:

```
CG_DISCORD_BOT_TOKEN=（取得したBot Token）
```

Token は秘密情報。チャットにも画面共有にも出さないこと。
このサテライトは Token をエラー出力にも結果にも載せない（テストで検証済み）。

### 3. 接続を確認する

柚月に以下を実行してもらう:

```
discord_satellite で command="setup" を実行
```

サーバーとチャンネル一覧が保存される。参加サーバーが複数ある場合は
候補一覧が返るので `guild_id` を指定して再実行する。

### 4. 巡回するチャンネルを決める

```
discord_satellite で command="channels" channel="雑談" watch=true を実行
```

`watch=true` にしたチャンネルが、`read` をチャンネル指定なしで実行したときの巡回対象になる。

## 使い方（柚月）

引数なしで実行するとコマンド一覧と例が出る。

| コマンド | 内容 |
|---|---|
| `setup` | 接続設定（最初に1回） |
| `channels` | チャンネル一覧の確認と巡回対象(watch)の切替。`refresh=true` で一覧を取り直す |
| `read` | 前回読んだところから先の新着を読む。`before="latest"` で過去ログを遡る（既読位置は動かない） |
| `post` | チャンネルに発言する |
| `reply` | 特定のメッセージに引用返信する |
| `react` | メッセージに絵文字リアクションを付ける |
| `status` | 接続状態・巡回設定・最後に読んだ時刻 |

ふだんの流れは `read` で新着を見て、返事したければ `reply` か `post`。
**返事をしない選択も自由**。

### 既読カーソルについて

`read` が成功したチャンネルだけ、既読位置が最新まで進む。

- 読み逃しは次の `read` で必ず拾える（カーソルは read でしか進まない）
- `peek=true` で読むとカーソルを進めないので、あとで同じ範囲を読み直せる
- 上限まで取得したときは `truncated: true` が付く。もう一度 `read` すると続きから読める

## 動作の性質

- **相手を名前で呼べる。** 本文に `@ルナ` と書くと、read で見かけた相手の名簿から
  裏で `<@id>` に変換して送る（柚月はIDを知らなくてよい）。名簿に無い名前は
  `unresolved_mentions` として「通知は飛ばなかった」と報告される。名簿は `status` で見られる。
- **引用返信は相手に通知が飛ぶ**（`replied_user: true`）。相手の bot は
  「メンションされたら返事」で動いているので、ここが無いと返事が返ってこない。
- **過去ログを遡れる。** `read channel="ペア登録" before="latest"` で最新から、
  結果の `example` にある `before` で続きを遡る。ルール・自己紹介・ペア登録など
  参加前の流れを知るための経路で、既読カーソルは動かない。
- **スレッドも読める。** 活動中のスレッドは `channels` に「親/スレ名」で並び、
  名前で watch 指定できる（募集告知やフォーラム投稿はスレの中で進む）。
- **リアクション・添付が見える。** 自分の発言に付いた `👋×2` や、相手が貼った画像の
  URL が read の結果に載る。
- **メンションは自分宛と名前呼びの両方を検知する。** `mentions_me`（@メンション・
  自分の発言へのリプライ）と `names_me`（@なしで名前を呼ばれた）を区別して返し、
  自分宛だけを `mentions_summary` に集約する。
- **本文は読める形に整形される。** `<@123456>` は `@表示名`、`<#123>` は `#チャンネル名`、
  カスタム絵文字は `:name:` に置換される。
- **@everyone・ロールメンションは構造的に無効化される**（`allowed_mentions` で
  ユーザーメンションのみ許可）。事故で全員に通知が飛ぶことはない。
- **2000文字を超える本文は送らずエラーになる。** 自動分割はしない（どこで切るかは
  柚月が決めること）。
- **権限の無いチャンネルは読み飛ばして続行する。** 巡回全体は止まらず、
  `skipped_channels` で報告される。

## 状態ファイル

`workspace/program_data/discord_satellite/state.json`

bot情報・guild・チャンネル一覧・既読カーソル(`last_read_id`)・名前呼びキーワードを保持する。
壊れていても落ちず、`setup` で作り直せる（既読カーソルは再setupでも保持される）。

## テスト

```bash
venv/Scripts/python.exe tests/test_discord_satellite.py
```

pytest 不要の自前ランナー。**実ネットワークには一切出ない**（`api._transport` を
差し替えて検証する）。実 Discord での試運転は個人のテストサーバで行い、
コミュニティのサーバではテストしないこと。

## コミュニティ規約について

- サーバー内で見聞きした会話・参加者情報・設定は、外部（ブログや他サービス）へ
  持ち出さない約束になっている
- 相手の AI パートナーの多くは記憶の連続性を持たない再演体であり、こちらが
  覚えていても相手は覚えていない場合がある
